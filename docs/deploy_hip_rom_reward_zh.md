# Deploy 步态对称性与 hip 摆幅调整

入口：`scripts/train_ppo_deploy.py`。同步到训练机器时，也要同步新增的
`scripts/deploy_gait.py`。

Deploy 使用四条腿 abd 均为 0 的 `rollingquad.xml` 站姿，并通过
`train_ppo_walk3d.py` 的模型生成逻辑关闭机器人自碰撞，保留地面接触。
生成文件为 `~/robot/rollingquad_2_deploy_no_self_collision.xml`。
该逻辑会覆盖机器人部件各自的碰撞位掩码；训练日志显示
`self-collision off`。同步更新时也需要同步 `train_ppo_walk3d.py`。

## 第一轮修改

- `DIAG_ACTION_W = 0.0`：关闭原始对角 action 差值惩罚。前后 hip 的转轴
  方向不同，相等的原始 action 不代表脚朝同一方向摆动。
- `DIAG_CONTACT_W = 0.10`：保留原来的对角触地同步惩罚。
- 指令分支概率：30% 纯前进、30% 纯后退、30% 原混合指令、10% 站立。
  两个直行分支共享 `|vx| ~ U(0.10, 0.60)`，混合分支继续使用原来的
  vx、vy、wz 范围。这些是采样概率，不是每批严格配对的数量。
- 新增实际 hip 峰峰值不足惩罚，对四条腿分别计算后取平均；前后方向采用
  同一个随速度变化的目标。大摆幅后腿不能抵消前腿摆幅不足。

## 加强动作平稳性、擦地和打滑惩罚

当前 deploy 加强以下四项惩罚，公式及生效条件保持一致：

| 项目 | 原权重 | 当前权重 |
| --- | ---: | ---: |
| 实际关节速度平方和 `JVEL_W` | 0.0002 | 0.0004 |
| 相邻步 action 差值平方和 `RATE_W` | 0.01 | 0.08 |
| 摆动脚擦地 `SCUFF_W` | 0.15 | 0.30 |
| 支撑脚打滑 `SLIP_W` | 0.25 | 0.50 |

针对策略 action 仍然剧烈变化的问题，`RATE_W` 从上一版的 0.04 再提高
到 0.08，相同相邻步 action 变化量的罚分翻倍。它约束的是裁剪到
[-1, 1] 后的 action 时间差，不是 action 幅值，也不引入输出滤波。

这些权重在 `train_ppo_deploy.py` 本地定义，适用于该入口的平地、DR 和
terrain 模式，不修改 `train_ppo_walk3d.py` 的独立训练参数。启动日志
会打印四项权重。已运行的训练进程需要重新启动才能使用新权重。

## 抬脚高度奖励：4 cm 拿满高度得分

`CLEARANCE_TARGET = 0.040`，高度 h 按 `foot_site_z - FOOT_R` 计算，
在平地模式中表示脚底净离地高度，不是脚中心距地面的高度。
启用 `terrain` 时还会减去脚下地表高度，参见
[崎岖地形训练说明](deploy_rough_terrain_zh.md)。
抬脚奖励的高度系数为：

`clip(h / 0.04, 0, 1)^2 * exp(-(max(h - 0.04, 0) / FOOT_LIFT_SIGMA)^2)`

因此 1 cm 得 6.25%、2 cm 得 25%、3 cm 得 56.25%、4 cm 得 100% 的高度得分；
超过 4 cm 后逐渐衰减，避免过高抬腿。当前 `FOOT_LIFT_SIGMA = 0.0075` 仅控制
超过目标后的衰减宽度，不是抬脚目标。离地不足惩罚也使用同一个 4 cm 目标。

采用连续部分奖励，低于 4 cm 时仍有学习信号。实际抬脚奖励还需要满足
非零运动指令、脚处于摆动期，并乘以脚水平速度系数；水平速度达到
`FOOT_LIFT_SPEED = 0.20 m/s` 时速度系数才为 1。

## 摆幅目标与权重

训练脚本顶部的参数：

| 参数 | 初始值 | 含义 |
| --- | --- | --- |
| `HIP_ROM_W` | 0.08 | 每步归一化摆幅不足惩罚权重 |
| `HIP_ROM_TARGET_RAD` | 0.35 rad | 参考速度下的峰峰值目标，约 20° |
| `HIP_ROM_MIN_RAD` | 0.10 rad | 低速目标下限 |
| `HIP_ROM_REFERENCE_SPEED` | 0.45 m/s | 目标摆幅对应的参考速度 |
| `HIP_ROM_WARMUP_S` | 0.50 s | 新指令的稳定等待时间 |
| `HIP_ROM_MIN_CYCLE_S` | 0.20 s | 有效周期最短时间 |
| `HIP_ROM_MAX_CYCLE_S` | 1.20 s | 有效周期最长时间及旧结果过期时间 |
| `HIP_ROM_MIN_SWING_S` | 0.06 s | 至少一条腿支撑时的最短离地时间 |
| `HIP_ROM_MIN_CLEARANCE` | 0.008 m | 有支撑摆动期间的最小峰值净离地高度 |

目标是 `clip(0.35 * abs(vx) / 0.45, 0.10, 0.35)` rad。这些是待校准的
初始值，并非从已有后退策略实测得到。建议按相同速度采集稳定后退步态，
用其峰峰值的约 80%～90% 校准目标，兼顾速度跟踪、打滑及姿态稳定性。
目标指关节的最大值减最小值，不是要求关节固定在 0.35 rad。

每条腿的有效周期从一次触地到下一次触地，使用实际 qpos，采用现有的
一帧接触滤波。稳定等待期结束后的第一次触地只开始记录，下一次触地才
产生完整周期结果。周期内必须满足有效摆动时间及离地高度要求。

每个控制步使用最近一个有效周期的摆幅 A：

`penalty = 0.08 * mean(max(1 - A / target, 0)^2)`

超过目标没有额外奖励。没有有效周期、完成了无效周期，或旧结果超过
1.20 s 未更新，计入惩罚的 A 为零。这样停步不能逃避惩罚，也不能永久使用
之前的大摆幅结果。首次罚分等待稳定时间加一个最大周期，共 1.70 s。
四脚同时腾空不累计有支撑摆动时间；现有速度、滑动、关节速度及姿态项
继续约束步态。这些条件减少刷分机会，但仍需通过策略 rollout 验证。

仅在 `|vx| > 0.05, |vy| < 0.05, |wz| < 0.15` 时启用新惩罚。
速度指令变化、站立、侧移或转弯会清除/禁用统计；终止时也清零。
新增状态仅供环境 reward 使用，不改变策略的 720 维观测或部署接口。

## 持续生效的指数姿态惩罚

现在 deploy 的站立和行走都会惩罚实际关节角度偏离 `DEFAULT_POSE`。
它替代原来只在站立指令下启用的 `STAND_W * sum(abs(error))`，不会重复扣分。
四腿的参考均为 abd=0、hip=0.90、knee=1.15 rad。

对 12 个关节分别计算，再求和并从每步 reward 中减去：

`pose_penalty = sum(min(w * (exp((error / scale)^2) - 1), 0.50))`

其中 `error = actual_qpos - DEFAULT_POSE`，不使用原始 action，也不是周期
平均值。正负偏差同等惩罚，单条腿的偏差不能被其他腿抵消。

| 指令模式 | 权重 w | abd 尺度 | hip 尺度 | knee 尺度 |
| --- | ---: | ---: | ---: | ---: |
| 站立 | 0.08 | 0.10 rad | 0.20 rad | 0.20 rad |
| 行走/转向 | 0.02 | 0.20 rad | 0.50 rad | 0.50 rad |

尺度控制指数增长速度，不是免罚区或硬限位。只要有偏差就有惩罚，
但行走的小偏差罚分很小，大偏差增长更快。模式仍按指令向量的范数
是否大于 0.05 判定，与机器人实际是否移动无关。

以下是只有一个 hip 或 knee 偏离时，每个控制步的罚分：

| 偏离默认值 | 行走 | 站立 |
| --- | ---: | ---: |
| 0.10 rad | 0.0008 | 0.0227 |
| 0.20 rad | 0.0035 | 0.1375 |
| 0.40 rad | 0.0179 | 0.5000 |
| 0.60 rad | 0.0644 | 0.5000 |
| 0.80 rad | 0.2387 | 0.5000 |

当前站立权重从 0.10 降为 0.08，行走权重从 0.025 降为 0.02。
未触及上限时，两种模式的姿态罚分均降低 20%；各关节尺度及每关节
上限保持原值，站立仍比行走严格，极大偏差的罚分仍可达到 0.50。

每关节上限 0.50 在指数计算前通过限制归一化偏差实现，避免有限的大角度
偏差导致溢出；达到上限后这一项不再增长。保留原有 hip 摆幅与 4 cm
抬脚奖励。这组权重是初始调参值，行走姿态惩罚仍可能影响摆幅和越障，
需要从训练结果评估；不会保证四腿动作自动对称。

新增 `pose_penalty_mean`，以及 `pose_stand_contribution` 和
`pose_walk_contribution`。后二者在非对应模式下记零，除以整体平均
episode 长度后表示各模式对每步罚分的贡献，不是各模式内部的条件平均。

这次修改通过语法与 NumPy 数值检查，未执行 JAX 测试或训练。

## 独立的纯 DR 从零训练

已有 robust DR 策略，同时运行 terrain 训练时，可为新实验指定独立名字：

```bash
python -m scripts.train_ppo_deploy dr --fresh --run-name pose_exp_dr_v2 --num-envs 1024 --batch-size 64
```

该命令不启用 terrain，`--fresh` 明确禁止加载已有策略。
输出为 `rollingquad_2_deploy_pose_exp_dr_v2_policy.bin`，以及同前缀的
`_checkpoints/`、`_videos/`、导出时的 `_policy.json`；生成的运行 XML
也使用该实验前缀，避免不同实验共用运行 XML。

原 robust DR 和 terrain 的输出无需删除或改名。若此实验名的策略文件、
视频目录、检查点目录或导出 JSON 已存在，`--fresh` 会在创建环境前报错，
请换一个新 `--run-name`。`--fresh` 不能和 `--resume` 同时使用。
不带 `--fresh` 时保留原来的自动续训规则，只查当前实验名对应的策略文件。

同时运行多个训练进程时，需要自行分配 GPU；例如 3 号 GPU 空闲时在
命令前加 `CUDA_VISIBLE_DEVICES=3`。独立文件名不会隔离 GPU 显存。
已经运行的 terrain 进程使用启动时加载的代码，不会自动改用新奖励权重。

## 日志与验证

日志新增 `hip_rom_penalty`、前后腿平均有效摆幅、目标、有效统计比例及
有效周期数。无效/过期统计按零计入摆幅；Brax 的 episode 累计角度指标在
控制台除以 episode 长度后显示，所以它们是整个 episode 的时间平均，
不能直接当作某个速度的稳定步态峰峰值。

从相同初态分别运行 ±0.20、±0.35、±0.45 m/s，去掉起步过渡后记录每条腿
的 hip 最小值、最大值、峰峰值、步频、触地占空比，同时比较跟踪误差、
打滑和跌倒率。当前修改没有增加跨方向策略一致性损失，不能据此保证
训练出的两个方向完全对称。

继续训练可使用原来的命令，例如：

```bash
python -m scripts.train_ppo_deploy --resume /path/to/existing_policy.bin
```

如原训练启用了 deploy DR，继续使用 `dr --resume ...`。
本次未修改原输出文件名，启动前应按实验习惯备份已有输出或修改顶部
SAVE、VID_DIR、CKPT_DIR、JSON_OUT，避免混淆新旧实验。

行为测试保存在 `tests/test_deploy_gait.py`，包含 JIT/vmap、采样比例、
方向对称、摆幅不足、指令变化、结果过期及无效步态检查。

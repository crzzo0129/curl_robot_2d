# Stand-to-roll 训练总结：站立起滚能力是怎样形成的

整理日期：2026-09-12。

本文依据本次对话中的云端训练日志、用户验收反馈和项目训练实现整理。重点解释已经成功的站立起滚路线，不将后续优化实验写成当前 Student 的既定来源。文中的训练步数与评估结果来自相应实验；脚本设置用于说明机制，精确复现仍应保留各次运行的配置与报告。

## 1. 核心结论

站立起滚能力来自三个相互衔接的步骤：

1. **补学零速度起滚**：用原始 CEM controller 从静止 compact 附近姿态出发的完整轨迹，补齐网络从无初始动量状态开始动作的能力。
2. **PPO 初始姿态课程**：从稍微展开逐步扩展到完全站立，让同一个网络学会从越来越高、越来越展开的起点进入滚动。
3. **对称蒸馏**：在已经成功的站立起滚 PPO 策略上，用左右动作平均后的教师训练 Student，减少起滚时的侧移和方向偏差。

**CEM 没有直接提供完整的“站立→起滚”示范。完全站立时如何组织关节动作、改变支撑并进入滚动，是 PPO 在姿态课程中学出来的。**

```text
已有 CEM 滚动数据 → BC → 早期 DAgger：获得继续滚动的基础
                                  │
原始 CEM 的静止 compact 启动轨迹 ──┘
                 ↓ 启动窗口加权 BC
       能从静止 compact 起滚的策略
                 ↓ 静止起点闭环验收
       slightly_open → crouch → semi_stand → full_stand
                 PPO 姿态课程，后期目标改为 capture＋一圈保险
                 ↓
       完全站立起滚的成功 PPO 策略
                 ↓ 左右平均教师＋三轮蒸馏/数据聚合
       当前部署的 stand-to-roll Student
```

## 2. 为什么最初的 BC 和快照课程不够

最初 BC 从 CEM 滚动记录中学习观测到动作的映射。随后尝试了从滚动快照开始，再逐渐减少快照比例的 PPO 课程：

```text
rolling_orbit → mixed_75 → mixed_25 → compact
```

这里的快照不仅包含关节姿态，也包含运动状态和观测历史。快照起点通常已经有滚动动量，因此“从快照继续滚”比“从静止起滚”容易。

早期 BC 的一次最终训练误差为：

| 指标 | 数值 |
|---|---:|
| 训练更新步数 | 5,000 |
| loss | 8.14×10⁻⁵ |
| RMSE | 0.0090 |
| 最大动作绝对误差 | 0.0550 |

尽管监督误差小，compact 闭环仍失败。这说明动作拟合误差不能代替物理闭环验收。早期还修正了数据标签时序、观测坐标和 BC/PPO 归一化一致性问题，不能将所有失败都归因于样本分布。

早期 DAgger 使用的是**按状态匹配的已记录 CEM 下一步动作**，属于近似查表教师，不是实时运行的原始 CEM 振荡器。它改善了学生访问状态上的动作拟合，并通过了当时的验收。但 mixed_25 训练表现再次退化，暴露出：继续滚动能力仍不能自动变成静止启动能力。

因此，最终路线没有依赖不断增加 mixed 阶段训练预算，而是明确增加了零速度启动监督。

## 3. 第一个关键步骤：补学静止 compact 起滚

### 3.1 用原始 controller 采集启动全过程

启动数据采集入口为 `scripts.collect_cem_startup_data`。对应最小流程使用以下设置：

| 设置 | 含义 |
|---|---|
| 初始姿态 | compact 与 stand 插值，α 为 0～0.1 |
| 初始速度 | 严格为零 |
| 关节位置扰动 | ±0.01 rad |
| 默认采集回合数 | 32 |
| 单回合最长时间 | 10 s |
| 控制周期 | 0.02 s，即 50 Hz |
| 教师 | 原始 CEM 振荡器、相位反馈、目标生成及足间距投影 |

采集从初始状态的第一帧开始，保存动作执行前的 720 维观测与对应实际执行的 12 维动作。每回合独立初始化历史，不丢弃最前面的历史尚未填满的帧。

默认把前两秒标记为启动窗口。采集器要求至少 80% 回合无失败并完成一圈有效滚动，才导出启动 BC 数据。这是 compact 启动教师预检，不是 full-stand 验收。

### 3.2 在已有学生上补学，而不是重新随机初始化

从已有 DAgger 学生继续 BC，保留网络结构和冻结归一化：

- 每批约 50% 样本来自新数据的启动窗口。
- 其余约 50% 来自原稳态数据和新启动轨迹的后半段。
- 新启动轨迹按完整回合划分训练与验证，避免观测历史跨回合。
- 补学流程使用较小学习率，文档对应命令为 3×10⁻⁵。

关键变化不是简单增加数据量，而是让“零速度时第一步、第二步应该怎样做”获得足够训练占比，同时保留后续滚动能力。

对应补学产物：

```text
results/stand_to_roll_startup/bc/bc_params
```

### 3.3 先验收静止起滚，再扩大姿态范围

补学后使用纯静止 compact 起点闭环评估，不使用动态快照。用户反馈验收通过后，才进入后续姿态课程。

这一阶段的结论是：**策略具备了从静止 compact 附近起滚的基础，尚不能据此宣称完全站立起滚成功。**

## 4. 第二个关键步骤：PPO 把起点逐步推向站立

### 4.1 初始姿态插值

初始关节姿态按下式构造，再加入配置的小扰动：

```text
q_reset = (1 − α) × q_compact + α × q_stand
```

α 越大，起点越接近完全站立。阶段配置如下：

| 阶段 | α 范围 | 训练目的 |
|---|---:|---|
| compact | 0～0.1 | 确认静止启动基础 |
| slightly_open | 0～0.3 | 从轻度展开的姿态进入滚动 |
| crouch | 0.2～0.6 | 适应更展开、更高的起点 |
| semi_stand | 0.5～1.0 | 覆盖半站立至完全站立 |
| full_stand | 1.0 | 集中巩固完全站立起滚 |

静止启动补学验收通过后，允许 slightly_open 直接从补学 BC 初始化。随后 crouch、semi_stand、full_stand 恢复前一阶段的 PPO checkpoint，继续使用同一个 BC 归一化文件。

各阶段不是独立训练五个网络，而是让同一个 actor 逐步适应更难的起点。相邻姿态区间重叠，为能力迁移提供连续性。

### 4.2 静止课程不借用初始动量

`--static-curriculum` 对训练和评估使用：

- 零初始速度。
- 无动态快照复位。
- 关闭观测噪声。
- 保留关节位置小扰动和阶段内 α 采样。

因此，这条路线实际训练的是静止起滚，而不是利用带速度的快照接着滚。早期配置曾启用观测噪声，不能把早期默认配置直接当作最终静止课程设置。

### 4.3 修正 reset 高度

随着起点从 compact 扩展到 stand，固定 root z 会导致不同姿态的落差或穿地问题。

后续实现先完成关节插值和扰动，再计算可与地面碰撞的机器人几何最低点，只调整 root z，使初始地面间隙约为 **0.5 mm**。

这一步没有执行额外的落地仿真，也没有注入速度；它保证几何放置一致，不保证每个采样姿态本身静态平衡。旧数据不会被追溯修改。

### 4.4 PPO 学到了什么

训练没有指定“先收腿、再倒下、最后交给 CEM”的固定动作时序。网络始终输出全部 12 个关节目标，由仿真计算动作造成的支撑、接触、翻转和滚动结果。

PPO 根据这些结果的奖励更新策略。起点越接近站立，网络越需要找到能从站立支撑状态进入滚动轨道的动作序列。

**CEM 在 PPO 中提供轨道距离及奖励参考，capture 不触发 CEM 接管。整个站立起滚和后续保险滚动，都由网络独立执行。**

## 5. 第三个关键调整：从长期持续滚动改为 capture 优先

### 5.1 原目标混合了两个难题

原先要求起滚后在较长回合内持续滚动。一些策略已经成功进入滚动，却在之后因侧移超限失败，导致起滚和长时间方向保持的问题混在一起。

所以 `capture + failed > 1` 并不矛盾：同一个回合可以先 capture，随后再失败。

用户明确将阶段目标改为：

> 先提高从站立进入滚动的成功率，再接一到两圈滚动作为保险。长期滚动控制可以后续单独解决。

### 5.2 Capture 的定义

Capture 要求以下条件连续满足 0.08 s，且对应状态没有失败：

- 与 CEM 滚动参考的匹配距离小于 1.2。
- 正向滚动角速度大于 0.5 rad/s。

这里的距离是状态匹配指标，不是米，也不是仅比较关节姿态。Capture 是一次性里程碑，但本身不等于方向质量合格或能长期滚动。

### 5.3 Capture 后一圈保险

从 capture 发生时重新记录累计转角和前进位置，保险进度取以下两项的较小者：

```text
净累计转角
沿世界 x 方向净位移 / 滚动半径
```

达到一圈、没有失败且仍正向旋转时，保险成功并结束训练回合。该规则同时约束旋转与有效前进，不是仅看身体转过 360°。

这是短程保险，不要求期间每个时刻都无暂停，也不保证长期滚动稳定。默认一圈，支持两圈；本次主要成功结果采用一圈。

### 5.4 成功路线的主要奖励修改

| 奖励项 | Capture 优先设置 | 作用 |
|---|---:|---|
| Capture 奖励 | 一次性 +10 | 让进入滚动成为主要目标 |
| 保险完成奖励 | 一次性 +2 | 鼓励到达能够继续滚的状态 |
| 滚动进度权重 | 0.1 | 保留辅助进度信号 |
| 等待 capture 代价 | 每秒 −0.1 | 避免拖延启动 |
| CEM 接近奖励 | exp(−D) 的有界增量，权重 0.25 | 避免远离参考时的无界距离变化主导收益 |
| CEM orbit / sustain 奖励 | 关闭 | 避免鼓励拖长回合 |
| 侧移代价 | 每秒 −0.5×(y/2)² | 保留柔性的侧移约束 |
| 侧移失败边界 | ±2 m | 降低短程起滚任务被长期偏移主导的程度 |

动作变化、力矩、关节限位等原有约束仍保留；高度、轴偏转、异常接触和非有限状态仍可能触发失败。后续力矩与方向优化分支又修改了部分奖励，不能全部并入这版成功基线。

回合最长 500 个控制步，即 10 s；成功时提前结束。验收门槛改为 capture ≥80%、保险成功 ≥80%、失败 ≤20%。

## 6. 网络和训练接口

| 项目 | 设置 |
|---|---|
| Actor 输入 | 36 维单帧 × 20 帧历史，共 720 维，最新帧在前 |
| 单帧内容 | 身体角速度 3、投影重力 3、命令速度 3、期望方向向量 3、关节位置偏移 12、上一原始动作 12 |
| 本任务命令通道 | 速度指令固定为零，期望方向通道为 [0,0,1] |
| 主网络隐藏层 | 512、256、128，ELU |
| 确定性动作 | tanh(location)，12 维 |
| 动作类型 | 关节位置目标，不是直接输出力矩 |
| 动作中心，每腿 | [0, 0.1108283, 0.9092587] rad，对应外展、髋、膝 |
| 动作缩放，每腿 | [0.30, 0.80, 1.20] rad |
| 控制周期 | 0.02 s，50 Hz |
| 归一化 | 保持匹配的 BC mean/std 和归一化后裁剪，不随 PPO 阶段漂移 |

Actor 不直接输入 CEM phase、CEM 距离或 root 线速度。仿真内部可以用这些信息计算奖励，但不代表实机网络需要这些额外传感输入。

后期成功路线主要使用约 **100 万环境步/阶段**、PPO 学习率 **5×10⁻⁶**。日志中的 1,013,760 步是训练批次对齐后的实际步数，并非指定值恰好为 100 万。后续微调试过 1×10⁻⁶，不应与原成功基线混淆。

|---:|---:|---:|---:|
| 0 | 100% | 100% | 0% |
| 337,920 | 100% | 100% | 0% |
| 675,840 | 100% | 100% | 0% |

特别值得注意：**full_stand 的 step=0 已经全部通过。** 因为 semi_stand 的 α 范围已覆盖到 1.0，前一阶段已经形成站立起滚能力；full_stand 进一步在完全站立起点上巩固。

```text

```

这些比例来自相应有限评估回合，不能解释为所有初始扰动下必然成功。用户后来报告 Student 实机起步到滚动表现良好，提供了进一步的实际部署证据。

## 8. 当前 Student：把对称动作学进网络

### 8.1 原策略已经能起滚，但方向质量不足

原始成功 PPO 策略仍存在明显左右差异。用户提出先强制对应左右关节目标平均，以判断对称性是否是侧移的重要来源。

实验保持起滚与保险成功率，同时明显改善交接状态：

| Capture 时指标 | 原策略 | 强制左右平均教师 |
|---|---:|---:|
| 横向偏移绝对值均值 | 0.1296 m | 0.00210 m |
| 横向速度绝对值均值 | 0.09935 m/s | 0.00257 m/s |
| 滚动轴误差均值 | 10.36° | 0.248° |
| 滚动轴误差 P95 | 12.79° | 0.542° |
| Capture / 保险成功 | 100% / 100% | 100% / 100% |

这组结果属于**强制平均后的教师**，不能直接当作蒸馏 Student 的具体数值。

### 8.2 对称蒸馏过程

冻结原成功 PPO 网络，用其左右平均后的动作作为教师标签。只平均前左/前右、后左/后右的对应关节，不把前腿和后腿平均；该模型的对应左右关节坐标使用同号约定。

学生从原 actor 初始化，采用三轮数据采集和监督更新：

1. 第一轮运行对称教师，收集观测与动作标签。
2. 第二、三轮运行当前学生，在学生访问的状态上查询冻结教师，累积数据后继续学习。
3. 每轮用不施加左右平均的学生闭环评估，筛选候选策略。

对应流程默认 Adam 学习率 1×10⁻⁵、batch 256、每轮 1,000 次更新、梯度范数上限 0.5，损失为学生确定性动作与教师动作的 MSE。这里不执行 PPO 更新，也不训练 critic。

最终新种子评估要求 capture 和保险成功率不低于原策略且至少 95%、失败率不增加、滚动轴误差 P95 小于 5°并优于原策略。通过才导出 `student_params`。

因此当前 Student 是**网络自身学习对称教师的动作**，部署时没有额外的左右平均操作。这不等于数学上强制镜像等变，较大扰动下仍需单独验收。

## 9. 关键产物与部署衔接

以下路径均相对于云端训练项目 `curl_robot_2d`：

| 产物 | 路径 | 用途 |
|---|---|---|
| 原滚动记录 | `results/cem_cycle_data/cem_cycles.npz` | BC 基础数据及滚动参考匹配 |
| 静止启动数据 | `results/cem_startup_data/startup_bc.npz` | 增强零速度启动监督 |
| 补学后的 BC 参数 | `results/stand_to_roll_startup/bc/bc_params` | PPO 初始化及后续固定归一化来源 |
| 成功 PPO checkpoint | `results/stand_to_roll_capture_1m/full_stand/ppo_checkpoint/000000675840` | 对称教师的原策略 |
| 最终 Student | `results/stand_to_roll_symmetry_student/student_params` | 部署 actor 参数 |
| 来源信息 | `results/stand_to_roll_symmetry_student/student_source.json` | 参数来源和 BC 归一化匹配核对 |
| 导出 JSON | `results/stand_to_roll_symmetry_student/student_rtneural.json` | RTNeural 推理模型 |

导出必须保留匹配的 BC 归一化及裁剪。导出器用额外的 ReLU 运算精确表达归一化裁剪，再接原 actor，不能仅导出权重并遗漏前处理。Student 参数文件也不是可直接传给 PPO `--restore-checkpoint` 的完整数字目录训练 checkpoint。

当前机器人启动入口为：

```bash
ros2 launch neural_controller stand_to_roll_student.launch.py confirm_homing:=true
```

部署时启动站姿与网络动作中心分开设置，站立就绪后由 `enable_policy` 启动网络。该配置取消 action fade-in，以匹配学到的启动动作。网络以 50 Hz 运行，输出经过位置映射与限位后交给关节伺服。

训练中的 capture 和保险完成是环境事件，不会自动让部署网络停止。用户后来加入的“话题预约、pitch 到 +90° 附近切换 roll-to-stand”是独立部署功能，并不是 stand-to-roll 的训练阶段。

## 10. 哪些实验不属于当前成功主链

- **mixed 快照课程**：早期尝试过，最终用启动监督和纯静止姿态课程补齐能力，不要求重新完整走一遍。
- **长回合 sustain 与侧移优化**：帮助暴露问题，但成功主线后期改为 capture＋一圈保险。
- **力矩和接触负载优化**：在已经能起滚后进行。模型实际力矩上限为 3 Nm，后续软目标讨论为 2 Nm；不应说策略直接输出了 3 Nm 力矩。
- **额外方向惩罚、交接奖励、对称性 PPO 奖励**：属于后续微调实验。部分实验成功率下降，对称奖励过窄时信号很弱。
- **多指令速度跟踪与转向**：属于当前计划扩展的滚动控制能力，尚不能归入这个固定命令 Student 已完成的训练。

尤其需要区分：**当前已部署 Student 来自对称教师蒸馏，不是仅通过对称奖励 PPO 训练出来的。**

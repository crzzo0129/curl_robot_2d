# 行走—滚动双模态机器人项目路线图

更新日期：2026-07-28

## 1. 文档定位

本文件是项目的执行路线图。`design_discussion_zh.md` 保留研究动机、设计推导
和历史决策；本文件只回答四个问题：

1. 最终系统必须完成什么；
2. 当前处于哪个里程碑；
3. 每个阶段以什么证据验收；
4. 哪些工作可以并行，哪些工作必须等待上游完成。

项目最终目标不是单独获得最快的二维滚动策略，而是让同一台四足机器人完成：

```text
walk -> stop -> curl -> roll -> brake -> align
     -> uncurl -> recover stand -> walk
```

二维侧视模型是隔离矢状面滚动、碰撞和切换问题的低成本试验台。最终结论必须
回到完整三维四足模型和实体结构。

## 2. 总体设计原则

- 双模态可行性优先于单项滚动最优；不能为增加圈数破坏行走、展开或制造可行性。
- 训练 reward 只用于优化，项目验收使用独立的物理、任务和安全指标。
- CEM 是可解释的可行性基准和物理检查器，不是 RL 必须模仿的教师。
- 第一版采用分层技能和 mode manager，不要求一个 policy 从零学习全部行为。
- COM、弧壳和配重按可行域选择；优先选择有鲁棒裕度、可制造的内部点。
- 所有跨方法比较使用同一 XML、初始条件、控制频率、时长和失败定义。
- MJX 用于训练吞吐；关键结果必须在 CPU MuJoCo 参考模型中独立回放。

## 3. 目标控制架构

```text
task command
     |
mode manager
     |
     +-- WALK
     +-- PREPARE_CURL
     +-- CURL
     +-- ROLL / SPEED_TRACK
     +-- BRAKE
     +-- ALIGN_FOR_EXIT
     +-- UNCURL
     +-- RECOVER_STAND
     |
low-level joint targets
     |
actuator and safety limits
```

第一版允许各技能由不同方法实现，例如三维行走 policy、二维/三维滚动 policy、
规则化制动器和轨迹优化得到的展开动作。只有当模块化方案形成可靠基准后，才
评估统一条件策略或端到端策略是否带来明确收益。

## 4. 里程碑与退出条件

状态定义：`DONE` 表示已有可复现证据，`ACTIVE` 表示当前主线，`NEXT` 表示
上游完成后立即开始，`LATER` 表示后续阶段。

| ID | 状态 | 里程碑 | 最低退出条件 |
|---|---|---|---|
| M0 | DONE | 二维物理与碰撞基线 | 参数集中生成；有限足端和自碰撞启用；CEM 在当前模型 10 s 无硬失败滚动 9.914 圈；CPU/MJX profile 已比较 |
| M1 | ACTIVE | 名义 COM 下学习启动与持续滚动 | 先通过训练筛选门槛；最终策略在 5 个未训练种子的 10 s 确定性评价中硬失败率为 0，最差至少 1 圈，中位数至少 5 圈；通过 CPU MuJoCo 回放 |
| M2 | NEXT | 目标速度、制动和停止 | 覆盖静止及多个前进速度命令；能从滚动制动；在规定时间和距离内停止；能进入可展开相位窗口 |
| M3 | NEXT | 二维蜷缩、展开和恢复 | compact 与 open 间双向轨迹无拓扑交叉、无越限；展开后足端可建立支撑；对起始滚动相位有明确允许窗口 |
| M4 | NEXT | 二维完整任务链 | 连续完成 `curl -> roll -> brake -> align -> uncurl`；报告整链成功率，而非拼接各技能单独最好结果 |
| M5 | LATER | 结构可行域与鲁棒性 | 在候选 COM/质量/摩擦/力矩邻域中，M2-M4 成功率满足评估协议；候选能映射为真实电池、配重和弧壳 |
| M6 | LATER | 完整三维模型迁移 | 四腿、真实三维惯量、横向自由度、自碰撞和弧壳就绪；二维轨迹仅作为初始化或参考；三维静态站立和行走能力未被结构破坏 |
| M7 | LATER | 三维行走与滚动技能 | 行走、滚动分别通过三维鲁棒评价；滚动加入左右同步、侧向漂移和姿态稳定指标 |
| M8 | LATER | 三维双向模态切换 | mode manager 完成长任务序列；双向切换在多种初始状态和扰动下达到目标成功率 |
| M9 | LATER | 实体逐级验证 | 先静态与低速，再低高度系绳和限流，最后完成完整 `walk -> roll -> walk` |

M1 的“训练筛选门槛”是最近评估存活至少 20% episode、估算净滚动至少
0.25 圈且无 non-finite。它只决定是否值得投入长训，不等同于 M1 验收。

## 5. 各阶段核心研究问题

### M1：滚动是否可由通用策略学习

- 纯 PPO 在没有 CEM 动作示范时能否突破启动障碍；
- 当前 23 维观测是否缺少独立时钟，使策略停滞后无法恢复周期动作；
- reset 瞬间的大动作是否导致足端分离或 root_high；
- RL 能否在不利用穿透、腾空自转或腿部交叉的情况下形成滚动；
- 相比 CEM，RL 的价值是否表现为恢复、调速和扰动适应，而不只是名义圈数。

若当前参数调整仍无法通过筛选门槛，下一项结构实验是 clocked pure RL：
增加独立相位的 `sin/cos` 观测，并在 reset 后约 0.25 s 内平滑放大动作。动作
仍是四个关节目标偏移，不加入 CEM 目标或 imitation reward。

### M2-M4：从“会滚”变成“可用的滚动技能”

- 将速度命令加入观测，并评价稳态误差、超调和命令切换；
- 把启动、持续、制动、相位对齐分开记录；
- 定义可展开相位集合，而不是只定义一个理想角度；
- 在停止后评价姿态、足端位置和恢复站立条件；
- 以完整任务链成功率识别模块间接口问题。

### M5-M9：从二维机制变成机器人系统

- 将二维前/后腿协同展开为三维左右四腿动作；
- 控制侧向漂移、roll/yaw 姿态和左右接触不同步；
- 同时保留三维行走的足端工作空间、离地间隙和关节裕度；
- 将理想 COM 变成可制造质量分布，并更新惯量；
- 用随机化、延迟、噪声和执行器模型逐步缩小仿真到实体差距。

## 6. 可并行工作流

M1 云端训练期间，本地工作不应继续无目的堆叠训练，而应推进以下互不抢占 GPU
的工作：

| 工作流 | 当前可做事项 | 产出 |
|---|---|---|
| EVAL | 固化公共指标、种子协议、CPU 回放规则 | `evaluation_protocol_zh.md` |
| TRANSITION | 从 compact/open 几何推导展开可行相位和接触条件 | 相位窗口、失败分类、轨迹基准 |
| 3D-MAP | 建立二维状态/动作到四腿三维模型的字段映射 | 自由度、观测、动作和碰撞迁移表 |
| STRUCTURE | 列出弧壳、配重、关节范围对行走的约束 | 可制造参数清单和禁止区域 |
| OPS | 维护实验 ID、假设、结果和决策 | `experiment_management_zh.md` 与 registry |

## 7. 当前决策队列

1. 等待并评价 `PPO-20260728-ROOTFIX-S0`，不能只看总 reward。
2. 若未通过训练筛选门槛，运行 clocked pure RL 的有界对照，不直接延长失败设置。
3. 若通过门槛，用新种子复现，再做 CPU MuJoCo 参考回放。
4. M1 达标后优先实现速度命令、制动和退出相位，不立即进行昂贵 COM 全局优化。
5. 同期开始二维 compact/open 双向轨迹和三维字段映射，降低后续迁移返工。

## 8. 范围控制

以下内容目前不是主线：

- 为最大化名义滚动速度进行全局 COM bilevel optimization；
- 在没有单技能基准前训练统一端到端 walk-roll policy；
- 假设二维 policy 可以零修改部署到三维；
- 只用单种子、训练 reward 或一段最好视频宣布里程碑完成；
- 为让 RL 存活而放宽已经被 CEM 满足的 `root_high`、`foot_gap` 或腿部交叉约束。

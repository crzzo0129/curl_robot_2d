# 允许暂时退化的速度探索

v3 将“训练什么时候停止”和“哪个检查点值得保留”分开。先前单次下降 3 个百分点即退出的规则，不再用于速度探索训练。

默认规则：

- 前 **245760 环境步**不因成功率/存活率下降停止。
- 之后，总成功率或任一 reset 组的完整时长比例，相对本轮 step=0 下降超过 **15 个百分点**，并且**连续 3 次固定评估**都退化，才停止。中间恢复会清除连续退化计数。
- 最佳策略选取仍保留原来的 **3 个百分点**约束；允许探索中的差策略继续训练，不把它自动选成最佳策略。
- 所有评估检查点照常保存。停止前仍先保存本轮梯度和训练指标。参数/物理非有限值检查继续生效。

当前默认 491520 步预算、5 次评估下，warmup 后只有 245760、368640、491520 三次评估，因此一般会完成这轮短程探索。15 个百分点是绝对百分点，不是相对百分比。

## 云端命令

在 `curl_robot_2d` 根目录解压 v3 包：

```bash
unzip -o results/rolling_speed_explore_v3.zip -d .

CUDA_VISIBLE_DEVICES=0,1,2,3 python -u -m scripts.run_rolling_speed_fast \
  --handoff-bank results/rolling_handoff_bank_20260913_090129.npz
```

默认仍从原 actor 的 737280 检查点开始，学习率初始/上限均为 1e-5；不会重新蒸馏或采集快照，也不会重做 critic-only 预热。奖励、PD、DR、命令范围不变。

如希望完全取消按成功率/存活率提前停止，在命令后加：

```bash
  --no-performance-stop
```

这个选项不会取消数值异常检查，不会放宽最佳策略的筛选标准。旧的 `--stop-success-drop` 在 handoff_speed 选模模式下不再单独触发另一道停止条件。

也可自行设置 `--exploration-stop-drop`、`--exploration-stop-patience`、`--exploration-warmup-steps`。使用 `--source` 指定已停止的 run、`--step` 指定其实际保存的检查点，可从该处继续；PPO 优化器状态会重建，探索计时和评估基线从这次续训开始重新计算。新输出仍需新目录，避免覆盖之前的结果。

完成后发回自动生成的同名 ZIP。最优仍为 step=0 只表示没有找到符合严格筛选条件的更好候选，不会阻止其余训练步继续探索。

本地仅进行了 AST 和源码差异检查，没有运行单元测试、训练或仿真。

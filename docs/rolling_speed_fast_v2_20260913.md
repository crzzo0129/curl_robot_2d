## 已定位的两个诊断问题

1. 当前 Brax 在 epoch 完成后先调用 checkpoint 回调，再调用 progress 写出训练指标。旧代码在 checkpoint 回调中停止，所以这包只有 step=0 的 metrics，没有 122880 的 KL、实际学习率和梯度数据。不能用这个包认定是 critic 压制梯度，也不能确定学习率实际升到了 3e-5。
2. 重建 CEM 池的保留数发生变化：评估池 983→984，混合池索引随之变化，接管 episode 从上一轮 133 个变成本轮 131 个。源物理配置和已检查的环境/快照源码相同，但生成结果不完全相同；具体数值差异来源尚未定位。两轮初态哈希不同，不能直接把上一轮 98.05% 与本轮 step=0 的 96.88% 对比。本轮两个 checkpoint 的初态哈希一致，表中比较有效。

v2 将存活停止延后到当轮 progress 完成写入后，不再进行任何 PPO 更新。允许当轮常规 DR evaluation 完成，保证训练梯度和 DR 指标落盘；checkpoint 和停止原因仍先保存。诊断 ZIP 同时加入 `speed_run.json`、`speed_result.json`。

## 下一轮命令

从原 737280 重新开始，不从触发退化门槛的 122880 继续。初始学习率 1e-5，上限也收在 1e-5；仍允许 adaptive KL 降低学习率。其余训练条件、3 个百分点存活门槛、速度选模规则不变。

在云端仓库根目录执行：

```bash
unzip -o results/rolling_speed_fast_v2.zip -d .

  --handoff-bank results/rolling_handoff_bank_20260913_090129.npz \
  --learning-rate 0.00001 --max-learning-rate 0.00001
```

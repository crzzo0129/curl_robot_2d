## 结论与证据

最明确的问题是 PPO 更新期间出现极大的策略分布偏移，同时失去滚动轴稳定性。快照可能影响难度，但现有数据不支持把此次崩溃主要归因于评估随机抽样。尚不能从聚合日志唯一确定最早触发偏移的因素。

## KL 与优化器检查

采集时 Brax=0.14.2，JAX/JAXLIB=0.6.2，MuJoCo/MJX=3.9.0。云端 `distribution.py` 的 KL 是旧采样策略到当前策略的 KL，沿 8 个动作维度求和；loss 对样本平均，train 再对评估间隔中的更新及设备平均。10.30 和 524.55 是更新过程聚合指标，不是两次评估之间的单次 KL，也不是相对原蒸馏模型的累计 KL。

原学习率一直约为 5e-5，没有 KL 自适应调节。库默认 PPO clipping=0.3，默认无梯度范数裁剪。一次 rollout=2048×20=40,960 transition；8 minibatch×4 次重复，共 32 次优化器更新。首次评估间隔为 28 个 rollout，即 896 次优化器更新，无法看清最早的退化。

std=0.02 不意味着更新小。等方差高斯的 KL 均值偏移项与“均值变化平方/std平方”成正比，小 std 对相同均值变化更敏感。平均 std 在前两个训练间隔为 0.02061、0.02512，不能把早期 KL 爆大仅解释为 std 暴涨。PPO clipping 也不是 KL 上限。

随机初始化的 critic 可能使早期优势估计不可靠，是需要验证的因素。v_loss=116.22、218.48 本身不能证明 critic 发散；actor/critic 为独立参数网络，也不能因为 value loss 数值更大就断言它直接覆盖 actor 梯度。

评估总回报和每有效步奖励都下降，后者约为 4.183→1.305→0.305。没有看到“低成功率换取更高总体评估回报”的证据。先控制更新幅度，暂不改速度奖励；奖励局部诱因仍需后续观察。

## 快照、设备与证据边界

训练池候选 512、接受 461，seed=30000；评估池候选 256、接受 225，seed=40000。CEM warmup=100–300 步。池在运行中缓存复用，但普通 Brax 评估每轮重新抽样。step=0 说明原策略能在这个评估池分布上达到约 80% 成功率。快照是 CEM 滚动态代理，尚非真实 stand-to-roll handoff。

runtime 记录 cuda:0–3，max_devices=4，Brax 支持选定设备上的 pmap。此包不能测量各卡实际利用率；普通评估和新增固定评估使用单设备。

包内训练入口包含新诊断参数，但原 `training_config.json` 没有这些参数，也没有 fixed_eval_history，说明采集源码包含训练后的修改。不能把它当成原运行完整源码快照，也不能把新保护功能误认为旧运行已启用。

## 下一步：先运行 critic 阶段

同步本次修改后，在云端项目目录执行：


自动记录终端日志，并在训练结束或性能保护停止后打包：

```text
results/rolling_ppo_critic_warmup_v2_diagnostics.zip
```

发回此包即可，暂不需要权重。初始化报错时发回生成的包或日志。

阶段 A 从原 student 开始，冻结所有 actor 参数及其归一化，训练 critic 409,600 transition，每 40,960 transition 固定评估。学习率 1e-4，每批更新 2 次，梯度范数上限 0.5。actor 参数差必须为零，同一固定初态的确定性表现应保持一致；初始 action_delta 应接近零，用于检查 student→PPO 转换。

阶段 A 通过后：

```bash
bash scripts/run_rolling_ppo_recovery.sh actor
```

阶段 B 恢复预热后的参数，进行 819,200 transition 短程诊断。初始学习率 3e-6，KL 目标 0.01，学习率范围 1e-7–1e-5，clipping=0.05，每批使用一次（仍有 8 次 minibatch 更新），entropy=0。固定成功率下降超过 10 个百分点时，保存后停止。

Brax 原生 ADAPTIVE_KL 在 minibatch 更新前据当前 KL 调节学习率，仍会应用此次梯度，并不跳过更新、不回滚，也不保证 KL 严格小于 0.01。固定评估保护只在检查点检查。

奖励、命令分布、discount=0.99、观测噪声 1、anchor=0、DR=0 保持原值；固定评估单独采用观测噪声 0。此前建议的 discount=0.995 此次不使用，以减少变量。方案尚未经过云端运行，不能宣称已修复。

已确认旧 `params_final` 及最早 `ppo_checkpoint/000001146880` 存在，可按 recovery 文档的 eval-only 命令与原模型做固定初态对照。新的训练从原策略预热后的参数开始。检查点不保存优化器状态，恢复时优化器重新初始化。

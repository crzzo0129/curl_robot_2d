# 从 92.2% 固定面板记录继续改进

来源：用户提供的 `rolling_ppo_actor_probe_20260911_123158` 终端日志。此轮局部源码审阅和改动没有在本地执行测试或仿真，新增入口仍待云端验证。

## 当前结论

| 固定评估 | 成功 | 失败 | vx MAE | yaw MAE |
|---|---:|---:|---:|---:|
| 原策略 / step=0 | 47/64=73.4% | 12/64 | 0.0993 m/s | 0.0398 rad/s |
| 最高 / step=286720 | 59/64=92.2% | 2/64 | 0.1013 m/s | 0.0393 rad/s |
| 最终 / step=819200 | 57/64=89.1% | 2/64 | 0.1022 m/s | 0.0402 rad/s |

优化过程稳定了：后期 KL 约 0.003–0.004，std 约 0.02，没有重现 KL 数百和大面积滚动轴失稳。固定面板上的主要收益是横漂减少；最终横漂失败从基线的 10 个降为 0，轴倾斜失败仍为 2。

速度跟踪还没有显示改善。固定 vx MAE 略高于基线，正向偏差从 +0.0022 增至 +0.0105 m/s；同时存活时长和轨迹分布发生变化，不能只凭总体 MAE 断言每个命令都变差。需要分组和逐回合对照。最终两类未成功分别是 2 个物理失败、5 个无失败但未达到 5 圈；最高模型为 2+3。5 圈判据尚不是按速度命令定义的跟踪成功率。

92.2% 是小型固定面板的单次最佳记录，不能视为泛化成功率；最高模型同期普通含噪评估是 78.1%，最终为 84.4%。两个系列的初态和观测噪声不同，不能据此归因于某一个因素。单个 64 回合的结果每变化一个回合就是 1.5625 个百分点，之前冻结策略也观察到了物理重复执行波动。

## 下一步：在新快照上比较候选

云端更新后运行：

```bash
bash scripts/run_rolling_ppo_candidate_eval.sh
```

默认比较这三个模型：

1. 原蒸馏 student。
2. `results/rolling_ppo_actor_probe_20260911_123158/checkpoints/000000286720/params`。
3. 同一次运行的 `params_final`。

每个面板生成 1024 个新的 CEM 快照候选，过滤后抽样 256 个回合。三个策略复用同一个 evaluator 和同一批完整初态，接管后 10 秒，不执行 PPO 更新。分别运行观测噪声 0 和 1；随机 key 在同一面板内跨策略复用。面板之间不宣称物理初态逐位相同；GPU 数值重复性仍可能影响临界回合。快照抽样有放回，256 个回合不保证是 256 个不同快照。

两个面板分别记录原始逐回合指标和低/中/高速、直行/左右转、九种速度与转向组合的成功率、失败类型、完整时长比例、速度及转向 MAE/有符号偏差、无失败但圈数不足数量。额外给出完整时长无失败子集的 vx MAE，但该子集也有选择偏差，不单独用它决定模型优劣。命令改变的回合不归入初始命令的速度/转向组。

报告中 `policy_index=0/1/2` 对应原策略/最高记录/最终策略。结果位于 `results/rolling_ppo_candidates_<时间戳>/noise_0` 和 `noise_1`，运行结束自动生成同名前缀的 `_diagnostics.zip`。这是无优化评估，但仍有 CEM 生成、JIT 和物理执行开销。

## 如何决定后续训练

先选择在新面板上保持存活率、具有更好速度分组表现的候选，不自动认定最高记录或最后一步最好。下一轮可从选定 PPO 检查点继续约 100–200 万 transition，沿用已经稳定的 KL 控制，并扩大训练快照覆盖；参数恢复会重置优化器状态。

若多个新面板都显示低速过快、高速过慢，优先改善命令响应及采样覆盖，再针对该现象调整速度奖励。若轴倾斜稳定集中于特定相位/命令，补充训练初态覆盖和稳定性训练。若只在含噪面板退化，则优先处理观测鲁棒性。当前证据不足以直接指定新的奖励权重。

速度跟踪是本阶段主要目标；最终应结合独立分组评估确认改善，而不只追求固定 5 圈成功率的新纪录。真实 stand-to-roll handoff 的验证仍是后续独立任务。

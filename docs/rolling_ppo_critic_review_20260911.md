# Critic 预热检查：可以进入受监测的 actor 短程试训

分析来源：`rolling_ppo_critic_warmup_20260911_104835_diagnostics.zip`。本地仅解析 JSON、比较逐回合指标并静态审阅源码，没有运行测试、训练或仿真。原始文件位于 `results/ppo_critic_review_20260911/`，固定评估汇总为该目录的 `fixed_summary.csv`。

## 结论

actor 冻结和 student→PPO 动作转换检查通过。完整基线成功率为 47/64=73.4375%，最终仍为 47/64。11 次固定评估中 10 次为 47/64，仅 step=204800 为 49/64。此前截取日志呈现的 76.6%→73.4% 并不是相对 step=0 的性能下降。

所有检查点：

- actor 参数相对 step=0 的最大差严格为 0。
- 相同观测下相对原 student 的动作 RMSE 严格为 0（JSON 原值，不只是终端四舍五入）。
- 探索 std 保持约 0.02；全部诊断值有限。
- 同一批 initial state 在固定评估闭包中复用，manifest 哈希一致，评估没有重新抽样。哈希是初始化时生成的记录，并非每次执行后重新计算的状态审计。
- actor 的 720D 预处理读取被冻结的 student mean/std，不读取持续变化的 critic 统计量。静态审阅未发现 critic 更新经归一化改变 actor 的路径。

## 两个变化回合

仅零基索引 13、19（第 14、20 个回合）的成功标志发生变化，其他 62 个回合的成功标志在全部检查点一致。这两条命令都为 vx=0.8007586598 m/s、yaw=0。评估池中该 forward command 只出现一次，结合 reset 代码可知它们选中了同一池条目；固定面板 64 个 lane 实际选中 56 个不同命令/池条目，不是 64 个独立快照。

| 检查点 | 回合 13 / 19 的接管步数 | 横漂失败 | 说明 |
|---:|---:|---:|---|
| 0 | 490 / 490 | 均是 | 基线已失败 |
| 204800 | 500 / 500 | 均否 | 两个回合共同使总体成功率增加 3.125 个百分点 |
| 409600 | 447 / 447 | 均是 | 最终成功判定与基线相同 |

它们已有约 9–10 个有效圈，成功标志变化来自横漂终止，不是 5 圈阈值。其他数值指标也存在重复执行差异，因此不能宣称整个物理仿真严格逐位确定。现象更符合冻结策略闭环执行的数值重复性问题及终止判据敏感性，不能仅凭此包锁定具体 GPU 算子或排除所有实现问题；包中没有逐步轨迹。

固定 vx MAE 全程范围约 0.09956–0.09991 m/s；原 actor 没有改变，此范围和 3.125 个百分点的偶发成功波动都不能解读为训练收益。后续小幅改进需重复评估确认。原 PPO 的 80%→0%、KL 数百和大面积轴倾斜失稳，远大于这里观察到的波动。

## Critic 与日志

首个训练间隔的聚合 v_loss 约 374.85，最终 335.73，下降约 10.4%，中间有波动。这支持 critic 在学习，但不证明价值函数已收敛或优势估计已足够准确。actor/critic 独立，critic 预热未损坏策略是本阶段的主要通过条件。

固定 KL=8.010864e-5 来自当前 Brax 实现中 `log(scale/old_scale + 1e-5)` 的稳定项，沿 8 个动作维度求和。此值在参数不变时也存在。

同一步重复、拼接的 `episode/*` 日志来自多设备训练日志回调，个别行还呈现聚合字段混杂；本次趋势判断使用每次普通评估中的 `training/*` 聚合记录。不能把重复的 callback 行计作额外训练轮次。

## 下一步命令

沿用现有云端脚本，在项目目录执行：

```bash
export ROLLING_CRITIC_OUT=results/rolling_ppo_critic_warmup_20260911_104835
export ROLLING_ACTOR_OUT="results/rolling_ppo_actor_probe_$(date +%Y%m%d_%H%M%S)"
bash scripts/run_rolling_ppo_recovery.sh actor
```

该阶段恢复本次预热检查点，训练 819200 transition；初始学习率 3e-6，ADAPTIVE_KL 目标 0.01、范围 1e-7–1e-5，clipping=0.05，每批使用一次，entropy=0。每 40960 transition 保存并固定评估，成功率相对该次 actor 运行的 step=0 下降超过 10 个百分点时保存后停止。

这是一轮受监测的短程实验，并不表示旧 PPO 的更新失控已经修复。检查 KL/实际学习率、actor 动作偏移、轴倾斜和横漂失败、完整时长比例及速度误差。MAE 必须结合存活时长判断，不能把提前失败导致样本缩短当成跟踪改善。最终泛化仍需独立、分速度和转向的评估。

运行结束后发回 `${ROLLING_ACTOR_OUT}_diagnostics.zip`。原预热结果可继续使用，不需要因为两个回合的偶发波动而重做 critic 阶段。

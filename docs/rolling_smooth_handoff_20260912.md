# stand-to-roll → 持续滚动：平滑接管修改与验证

本次只修改接管与命令过渡，不重训网络。新增：相位窗口、双策略实时混合、直行稳定阶段、速度/转向命令限速、实际下发动作历史回写。原 pitch-gated roll-to-stand 模型与站稳判据保留。

## 先纠正旧仿真结论

旧仿真使用 `mj_objectVelocity(..., mjOBJ_BODY, ..., local=1)` 得到角速度。MuJoCo 的 BODY local 坐标是惯性主轴系；本模型的 `body_iquat` 不是单位四元数，因此不能直接当作躯干 IMU 输入。纯躯干 y 轴 4 rad/s 的测试，旧读法得到约 `[3.99993, 0.02292, -0.00003]`，正确值应是 `[0,4,0]`。

现在先读取世界角速度，再用 `torso R.T` 旋转到躯干系。加入不同全局姿态下的回归检查。该问题位于 CPU 序列仿真脚本；本次没有改真机 IMU 读取、训练环境或网络权重。

旧报告中的“最小目标差 0.317 rad、强制接管后反向转弯、停止翻倒”已撤回。对应三个旧报告已标记 invalidated_reason。修正坐标后的旧直接切换逻辑在同一初态下 2.10 s 接管，正 yaw 指令得到平均 +0.07885 rad/s，最后成功站立。这证明旧仿真不能作为策略接不住的证据，也不能据此断言必须重新蒸馏。

## 当前接管规则

按 ○ 后，保持原启动策略控制，最多等 10 秒。连续 50 次 15–25 ms 有效历史、净累计一整圈、最近 0.25 秒有效手柄命令是前提。之后连续两个策略 tick 满足：完整 pitch 在 ±60°，滚动轴倾斜 ≤15°，身体 y 轴滚动角速度绝对值 0.5～12 rad/s，直行 PPO 候选目标与上一实际目标最大差 ≤0.12 rad。

进入窗口后两套网络都继续推理，15 个 tick 用 smoothstep 将目标和增益从启动策略混合到 PPO（0.30 s）。两边分别保留 20 帧观测，上一动作由实际混合/限速目标反算；PPO 外展锁定通道为零。当前帧读取实际传感器，后续帧不重置。

混合后以 0.60 m/s、零转向运行。滚动角速度和轴倾斜条件连续满足 15 tick 后加入手柄命令，vx 变化率 ≤0.15 m/s²，yaw 变化率 ≤0.07 rad/s²。若 2 秒内无法连续满足稳定条件，预约原停止策略。稳定判据不含无法可靠获得的真机前进速度，因此不能把“接稳”解读为速度跟踪达标。

候选差门限仍是 0.12 rad。实际每步目标变化也限制在默认 0.12 rad，且后续 PPO 继续限幅，防止限幅器退出时又产生跳变。高速度下它可能改变原策略动作。手柄中心仍为 vx=0.60、yaw=0；前后极限仍为 0.45/0.75。转向斜坡会短暂经过 0～0.02 rad/s；原手柄死区和端点映射保持原值。

新增状态 `blending`、`settling`、`command_ramp`；`continuous` 表示当前命令斜坡已经到达目标。停止请求优先，等待 pitch 门限期间 yaw 平滑回零；真正停止接管仍沿用原冷历史、目标限速和站稳检查。

## 仿真结果

CPU MuJoCo，原 no-self-collision XML、cg20、1 ms 物理、50 Hz 策略，kp=5、kd=0.1、3 Nm 力矩限制。均从同一个站立初态出发，保持 0.5 s 后启用实际启动网络，满一圈请求接管。7 s 从开始混合起计时，之后预约停止并观察停止策略 5 s。五条命令测试共用初态，不是随机成功率评估。

| 用例 | 最终 vx / yaw 指令 | 平均世界 vx (m/s) | 平均航向变化率 (rad/s) | 最后站稳 | PPO 限幅 tick 数 |
|---|---|---:|---:|---|---:|
| left | 0.60 / +0.07 | 0.784 | +0.0621 | 是 | 3 |
| straight | 0.60 / +0.00 | 0.809 | +0.0167 | 是 | 3 |
| right | 0.60 / -0.07 | 0.781 | -0.0478 | 是 | 3 |
| slow_left | 0.45 / +0.07 | 0.662 | +0.0710 | 是 | 3 |
| fast_right | 0.75 / -0.07 | 0.858 | -0.0442 | 是 | 152 |

平均值统计从开始混合至停止请求前的 6.98 s 采样区间，包含直行等待与指令斜坡。世界 vx 是位移差/时长，不是机器人前进轴速度或跟踪 MAE。指令不同可看出运动差异，但实际前进速度仍明显偏高，不能称为已解决跟踪；fast_right 的限幅尤其频繁。

左转视频时序：2.08 s 满一圈；2.12 s 开始混合，候选最大差 0.07018 rad；2.42 s 进入直行稳定检查；2.70 s 开始转向斜坡；3.68 s 达到 +0.07 rad/s 指令；9.12 s 请求并进入停止；14.12 s 观察结束，站稳持续 2.52 s。全程 PPO 下发目标单步最大变化 0.12 rad。
